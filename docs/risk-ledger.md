# Risk Ledger

此文件記錄新機種委外加工對齊系統專案在開發與使用過程中的潛在風險、防護措施以及後續計畫。

| Scope | Risk | Guardrail | Next action (Owner=self) | Revalidation gate | Rollback | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Excel 格式解析** | 若發包方擅自更改 Excel 欄位位置，導致前端讀取座標偏移或解析出錯。 | 在 `excelParser.js` 與 `excelExporter.js` 中加入儲存格內容校驗。若預期的標題文字（例如「委外加工廠」）與實際單元格內容不符，則拋出警示並拒絕解析。 | 加強邊界檢查邏輯，使解析工具能動態尋找標題關鍵字，而非僅依賴寫死的座標（如 A5, B2）。 | 每次用戶上傳 Excel 檔案時進行校驗。 | 提示用戶下載原始範本重填，或回滾至前一版穩定的 Excel 格式。 | **Active** |
| **Excel 樣式遺失** | 純前端 SheetJS 庫在寫出檔案時可能因版本限制或寫法問題導致原始 Excel 的合併儲存格或背景色遺失。 | 我們採用「複製原始 workbook 對象並局部修改儲存格值」的策略，避開重新建構 Sheet 的步驟。 | 在匯出前確認 Sheets 的 `!merges` 等屬性是否有被正確保留。 | 在每次匯出成功後，於本機以 Excel 實際開啟驗證外觀。 | 若外觀損毀，則提示用戶提供未寫入前之備份檔重新填入。 | **Resolved** |
| **本地暫存遺失** | 由於是 Serverless 前端，若瀏覽器重整，正在填寫的資料可能會消失。 | 已在 `App.jsx` 中實作 `localStorage` 快取機制，每當 `projects` 陣列變更時自動寫入 `localStorage`，重新載入時自動還原。 | 擴充表單欄位時確認 `localStorage` 儲存/還原鏈正常運作。 | 每次重整頁面或切換機種時驗證資料還原狀態。 | 手動清除 `localStorage` 快取或重新上傳 Excel。 | **Resolved** |
| **PDF 列印分頁溢出** | 當 PCBA 特殊備註或測溫點資料過長時，列印可能超出 A4 紙張範圍，導致分頁不齊。 | 在 `PrintReport.css` 中設定 `page-break-inside: avoid` 與在 C 項目 (試產報告) 前強制加上分頁，以確保格式排版。 | 測試不同內容長度下的 PDF 印出效果。 | 每次擴充表單欄位時進行列印測試。 | 微調列印 CSS 的字型大小或邊距。 | **Active** |
| **測溫點與包材 Excel 寫入** | 因 Excel 儲存格空間有限，擴增測溫點 (6點) 與 PCBA/FPCA 包材種類 (2列) 可能會覆蓋下方的儲存格，或超出原本儲存格的邊界導致顯示不全。 | 匯出時採用逗號拼接寫入原範本儲存格，且 PCBA 與 FPCA 的包材項目各自拼接並寫回 B25/B26，同時清空原有重複儲存格防疊影。 | 在 Node.js 中以單元測試 (testExcelFlow.mjs) 確保資料解析與還原的 100% 正確性。 | 匯出 Excel 重新載入時需 100% 還原所有 6 點測溫與保護貼選項。 | 若解析出錯，則預設回寫為純文字並保留原始 Excel 儲存格的文字。 | **Resolved** |
| **擴增治具回寫與解析相容性** | SMT刷錫載具與其他自訂治具在原始範本中無欄位，若動態新增列會破壞 Row 39/40 簽核欄位位置。 | 採用「拼裝回寫至 Row 38 儲存格」策略，A38 寫入載具選項，B38 寫入自訂治具名與數，避免破壞簽核版面。 | 在 `testExcelFlow.mjs` 中加入往返校驗。 | 每次修改匯出格式時執行自動化整合往返測試。 | 若解析失敗，則在前端還原為預設未選狀態。 | **Resolved** |
| **防呆欄位鎖定狀態遺失** | 若瀏覽器重整，React 記憶體中的欄位填寫者擁有權鎖定 (`_owners`) 可能會遺失，導致防呆失效。 | `_owners` 已內嵌於 `data` 物件中，隨專案資料一併寫入 `localStorage`；`SignOff.jsx` 的 `handleSignChange` 會寫入 `currentUser.unit` 至 `_owners`，重整後經由專案載入路徑自動還原。 | 評估跨機種的 `_owners` 一致性檢查，確保舊專案的 owners 格式與新版相容。 | 每次重載或切換機種時驗證 `_owners` 的還原狀態。 | 若暫存損毀，清除 `localStorage` 並提示使用者手動再次編輯。 | **Active** |
| **雲端協作儲存衝突** | 多人同時在線編輯同一個機種時，可能發生後者儲存覆蓋前者資料的情形。 | 採用 Debounce 自動儲存以減小衝突視窗，並且欄位編輯有 `_owners` 防呆擁有權校驗限制不同角色的修改區塊。 | 評估下一階段研發協作鎖定或即時 WebSocket 同步機制。 | 每次多端同時進行編輯時檢查儲存一致性。 | 回滾至 JSON 資料庫的上一版本或提示下載備份 Excel。 | **Active** |
| **多平台部署與安全標頭** | 多平台邊緣託管 (Cloudflare Pages / Netlify) 若未設定正確的 CSP 與 SPA 轉向，可能導致頁面重整 404 或外部非預期連線/點擊劫持 (Clickjacking)。 | 在 `public/_headers` (Cloudflare) 與 `netlify.toml` (Netlify) 配置 `/* -> /index.html` 200 回退，並注入嚴格安全標頭 (`CSP` 僅放行 Supabase 與 Google Fonts、`X-Frame-Options: DENY`、`X-Robots-Tag: noindex` 與 assets 長期快取)。 | 每次更新外部依賴或新 API 網域時同步維護安全標頭。 | 透過 `npm run build` 與 `npm run deploy:cf` 後以 DevTools/curl 驗證標頭與 SPA 轉向。 | 回退 `public/_headers` 或 `wrangler.jsonc` 設定。 | **Resolved** |
| **按鈕巡檢與無頭瀏覽器環境** | Linux CI 容器環境執行 Chrome CDP 自動化巡檢時，可能因 `/dev/shm` 限制 (64MB) 或缺少 GPU 支援引發瀏覽器崩潰或假性超時。 | 在 `scripts/buttonAudit.mjs` 中加入 `--disable-dev-shm-usage` 與 `--disable-gpu` 參數，設定 15~20 秒啟動寬限與自動重試保護，並整合於 `npm run qa:gate`。 | 監控本機與 CI 按鍵巡檢穩定度。 | 執行 `npm run qa:buttons` (及 `qa:gate`) 100% 通過無崩潰。 | 調整重試寬限時間或測試啟動參數。 | **Resolved** |
| **測試環境變數覆寫污染** | 執行離線按鈕巡檢時若以 `.env.local` 覆寫清空 Supabase 金鑰，其高優先權會污染本機 `npm run dev`，導致本機開發誤入離線模式且無法以雲端帳號登入。 | 採用獨立 `.env.offline` 並透過 `vite build --mode offline`（`npm run build:offline`）進行離線打包；登入頁增加本機管理員重設防呆機制。 | 維護 `.env.offline` 與 `package.json` 的 `build:offline` 指令，嚴禁任何測試腳本產生永久 `.env.local`。 | 執行 `npm run qa:gate` 與檢查 `loadEnv('development')` 正常讀取 `.env`。 | 刪除 `.env.local` 恢復標準環境。 | **Resolved** |
| **CI Lint Node 全域物件檢查** | 前端 Vite 設定檔若直接存取 Node `process.env`，在平坦化 ESLint Flat Config 嚴格瀏覽器環境下會判定為未定義變數而阻斷 CI 建置。 | 在 `vite.config.js` 頂部顯式加入 `import process from 'node:process'`，明確聲明 Node 全域物件。 | 在 pre-push 或 CI pipeline 前強制執行 `npm run lint` 驗收。 | `npm run lint` 退出碼為 0 且零錯誤。 | 補齊顯式 `node:process` 導入。 | **Resolved** |
| **全雲端上線架構與 CI 離網巡檢相容性** | 全站確立為 Cloudflare Pages + Supabase 純雲端模式（無離線）後，GitHub Actions CI 若遇子路徑設定錯誤或無外部資料庫連線，會導致按鍵巡檢超時失敗（Run 38819920657）。 | 在 `vite.config.js` 將 base 預設為根目錄 `/`（適配 Cloudflare Pages），於 `buttonAudit.mjs` 中自動剝離路徑前綴並注入 CDP Supabase 雲端認證與 API Mock，在 `deploy.yml` 注入 CI 測試金鑰。 | 監控 GitHub Actions 綠燈與 Cloudflare Pages 部署狀態。 | 執行 `npm run qa:gate` 且 20/20 按鈕全數通過。 | 回滾 `buttonAudit.mjs` 與 `vite.config.js`。 | **Resolved** |
